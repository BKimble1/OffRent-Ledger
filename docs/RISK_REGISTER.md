# Risk register

Ordered by expected damage. "Mitigation" means something in the repository actually does it.

| # | Risk | Likelihood | Impact | Mitigation | Residual |
|---|---|---|---|---|---|
| R1 | A user believes the app told the vendor, keeps getting billed, blames the app | Medium | **Severe** (legal, reviews, refunds) | Disclosure is a required render on every Contact-Vendor screen; status cannot advance without explicit user affirmation; banned phrasing is build-enforced; `StatusTransitionTests` proves the shortcut is impossible | Copy can still be misread. Needs one real user test. |
| R2 | The Xcode project does not open or build, because no `xcodebuild` existed to verify it | **High** | High (blocks everything) | Modelled byte-for-byte on the owner's existing working project shape; file-system-synchronized groups mean no per-file references to get wrong; `scripts/verify_repository.py` parses the pbxproj and asserts structural invariants | **Closed.** `xcodebuild clean build` succeeded on Codemagic (Xcode 26.4), app and widget, from a clean clone; CI has since moved to GitHub Actions. The project has still never been opened in the Xcode UI. |
| R3 | SwiftUI/SwiftData/StoreKit code does not compile (never type-checked) | **High** | High | Conservative, well-trodden API use only; Swift 5 language mode with `complete` concurrency checking so concurrency problems are warnings, not errors, on first build; all the hard logic lives in the layer that *was* compiled | **Closed.** Zero compile errors. It took four rounds to get there: a multi-line string literal, `UIImage` crossing an actor boundary, `Section(_:)` with a footer closure, `.map` on a non-optional String, a type-checker timeout, and AppIntents metadata interpolating a runtime value. Each has a build-enforced check now. |
| R4 | Rate estimate is wrong across a DST boundary or a time-zone change | Medium | High (money) | Calendar-day arithmetic, never 86 400-second arithmetic; explicit spring-forward/fall-back tests that were executed | Low |
| R5 | Money rounding drift | Low | High | `Decimal` everywhere, one rounding function, banker's rounding, executed tests including accumulation over 400 periods | Low |
| R6 | OCR mis-parse silently corrupts a record | Medium | High | Parser cannot write; review sheet is unconditional; only ≥0.80 confidence preselected; provenance retained; `ScanReviewCommitTests` | Low by construction |
| R7 | Entitlement loss destroys or hides user data | Low | **Severe** | `EntitlementPolicy` gates *creation only*; executed tests assert edit/resolve/delete/view all remain permitted at every entitlement state | Low |
| R8 | Notification storm / duplicates / stale reminders after edit | Medium | Medium | `ReminderPlanner` is pure and produces a deterministic set with stable identifiers; scheduler diffs desired vs pending and cancels obsolete | Delivery itself unverified |
| R9 | Asset orphaning or deletion of a referenced file | Medium | Medium | `reconcile(referencedPaths:)` only removes files not in the referenced set; executed test covers the dangerous direction | Low |
| R10 | Migration breaks an existing store | Medium | High | Versioned schema from v1 with a `SchemaMigrationPlan` in place before release. V2 (job-site place) and V3 (a contact and address on a company, a PO number on an agreement) are each optional attributes and a lightweight stage. V1 and V2 are kept frozen because they describe the store on any phone that has not updated — **build 7 shipped V2 to TestFlight, so that store exists on a real device**. Nothing is dropped, renamed or rewritten in either stage. `MigrationTests` opens a container on V3, asserts a stage exists for every consecutive pair, and round-trips every new attribute | Exercised on a fresh store, not yet against a real upgraded one. Build 8 is the first upgrade that crosses two stages |
| R11 | Bundle ID / app name already taken; team ID wrong | Medium | Medium | Everything centralized in one xcconfig; documented as unverified | External gate |
| R12 | Legal URLs 404 at review time | Medium | Medium | `AppConfiguration.legalURLsAreLive = false`; app renders bundled Markdown; `verify_repository.py` fails if a placeholder URL is presented as live | Low |
| R13 | Widget leaks sensitive detail on the lock screen | Low | Medium | Widget reads only a summary snapshot (counts, one aggregate estimate, one date) — never vendor, jobsite, equipment or invoice detail; snapshot type is structurally incapable of carrying them. This is what made the three accessory families safe to add | Low |
| R14 | Trademark conflict on "OffRent Ledger" | Unknown | High | Name centralized to one constant | External gate |
| R15 | The on-device model fabricates a figure that reaches a rental record | **High** if unguarded | **Severe** (money, and the product's entire "based on the terms you confirmed" promise) | The model only ever *proposes*. `ModelSuggestionValidator` drops anything whose quoted line is not a recognised line, whose value does not appear in the recognised text character for character, or that does not parse as its field's type; a rule-based suggestion always wins; and model confidence is capped below the preselect threshold so nothing it proposes is ever pre-ticked. Thirteen portable tests, one per failure mode, plus an app test asserting a fabricated figure never becomes a suggestion | Low by construction |
| R16 | The on-device model is unavailable and scanning appears broken | Medium | Low | `#if canImport(FoundationModels)` plus an availability check; the fallback proposes nothing and the rule parser's suggestions stand alone. The review screen says why, in one sentence | Low |
| R17 | A place search or reverse geocode leaks rental data | Low | Medium | `MKLocalSearch` carries a query string the user typed and nothing else; reverse geocoding sends a coordinate. Neither carries a vendor, an amount or a record. A confirmation's location stays a measured GPS fix rather than a chosen place, so the evidence claim does not change. The jobsite editor biases search towards the map's *visible region* rather than the device's location, so no location permission is involved at all | Low |
| R18 | A control looks enabled and does nothing | **Realised** — shipped in build 7 | High (the user cannot tell a broken app from a broken tap) | `Accept this invoice` stamped a column nothing on screen displayed and left the rental where it was, so a working tap and a dead one were indistinguishable. The decision is now a value — `InvoiceAcceptance.decide` — asked *before* the control draws itself: blocked means disabled, with the specific reason underneath and a route out. Twelve portable tests, and a UI test that accepts from Audit and relaunches | Low by construction. The general rule — a primary action either acts or explains — is not build-enforced, only this instance of it |
| R19 | Extraction confidently reports a number the document does not say | **Realised** in the parser | **Severe** (money) | Vision reads `4,18O.00` for `4,180.00` often enough to matter, and the old money pattern captured `4,18` and stopped — $418 for a $4,180 line, in the right place, at high confidence. The amount pattern now refuses any number followed by a letter, or by a separator with a digit after it, so a garbled amount becomes a field the user fills in with the raw line visible under Recognised text. `ExtractionFixtureTests` covers both the refusal and the legitimate case it must not break | Low. Other OCR confusions (`l` for `1`, `S` for `5`) are not detectable this way and remain possible |
| R20 | A jobsite is labelled with something that is not a name | **Realised** — shipped in build 7 | Low (usability, not money) | A rural site came back from map search with a placemark named `07820`, and the pin on Today said so. `PlaceNaming` decides now, falling through business name → street → town, and writing `Near 07820` rather than a bare code when there is genuinely nothing else. Sixteen portable tests, including the uppercase site names — `ZONE 4`, `PHASE 2` — that a looser rule would have thrown away | Low |
